# Verification boundary

## Local results

The actual production ESM plugin is exercised, not a rewritten view. The local suite has **25 passing tests**, including **17 Chromium browser-harness tests** plus 8 entry/normalization/privacy tests. It uses real React and React Query; gateway atoms, RPC results, events, contribution registry and the native SDK Button are explicit synthetic seams.

Canonical verification commands and retained final logs:

| Command | Result | Evidence |
| --- | --- | --- |
| `node --check desktop/plugin.js` | exit 0 | `.local/final-node-check.log` |
| `pnpm test` | 25 pass, 0 fail | `.local/final-tests.log` |
| `hermes plugins doctor --ci .` | **exit 1**, Desktop-only tooling limitation | `.local/final-doctor.log` |
| `hermes plugins validate . --install-deps` | exit 0; security safe; native SDK surface valid | `.local/final-validate.log` |

`node scripts/verify.mjs` reruns these exact commands, preserves complete logs, and writes `.local/evidence.json` containing exit codes, log SHA-256 values and a sorted file/size/SHA-256 inventory. **It exits 1 while doctor fails**; the receipt never converts that failure into a successful doctor check. `.local/` and `node_modules/` are git-ignored and not publication artifacts.

The inspected runtime doctor's Python loader requires `__init__.py` even for a package containing only `desktop/plugin.js`. The native-aware validator explicitly accepts that Desktop entry, skips Python capability probing and reports portable/no Python. A dummy Python shim was not added just to make doctor green. Treat Python registration-doctor coverage as **unavailable**, not as a native renderer failure or as a passing gate.

The tests initially found missing matching browser binaries and a too-broad screenshot keyboard assertion. Installing test browsers **inside this directory**, tightening the keyboard test, and inspecting screenshots revealed a narrow-layout grid min-size problem. The production layout now constrains min-width and tests main-surface horizontal containment, with scrolling confined to individual tables. Earlier logs (`test-run-01.log` through `test-run-05.log`) are retained in `.local/`, rather than replaced by invented successes. Early validator caution about browser binaries was eliminated by keeping dev browser artifacts under excluded `node_modules/`; final validation reports safe.

## Covered behavior

- Actual plugin registration, route mount, sidebar/palette payloads and command navigation.
- RPC request path with focused runtime ID; only `session.context_breakdown` is allowed by the synthetic host.
- Correct total/free conservation, proportional 100-cell rounding, over-budget and unknown-budget states.
- Provider/local/mixed provenance, independent category estimates, differing reported estimate total and row sum, zero conversation, Unicode and absent arrays.
- Nonfinite, negative, fractional, unsafe, coerced or otherwise malformed counts; untrusted CSS colors and raw body fields ignored.
- Loading, errors, bounded retry exhaustion/recovery, missing method, zero-window runtime rebuild, no session, busy and disconnect.
- Pending session/profile/reconnect race suppression; connection-qualified split-session routing, connection replacement, missing/ambiguous owner routes and older-SDK fallback/fail-closed cases.
- Completion/compression/reclaim invalidation, unrelated-session filtering and event/atom cleanup on disposal.
- Keyboard focus, individually scrollable tables, no horizontal overflow of the page/main surface, wide/narrow light/dark screenshots.

## Visual evidence

`docs/screenshots/harness-{light,dark}-{1280,390}.png` are generated by `pnpm test` / `pnpm screenshots`. Every screenshot is visibly marked **SYNTHETIC SDK HARNESS · PUBLIC DEMO DATA · NOT LIVE DESKTOP**. The export enlarges the harness viewport vertically to fit all content; the tested normal-height main surface remains scrollable. No real user session, private workspace path or prompt is present.

The harness uses selected real Nous theme seeds and the actual token formulas from the referenced runtime, with explicit MIT attribution. It does not replace dark text/control variables with invented fixes. It records sampled secondary text contrast above 4.5:1 in both modes in `.local/browser-visual-checks.json`; this is a sampled text check, not a claim of exhaustive WCAG conformance or native Button parity. `.local/browser-console.json` records browser runtime errors (empty on the successful run).

## Not established here

- Live Desktop loader/enablement, native SDK Button rendering, and connected runtime responses.
- An installed app-root copy, profile enablement, hot reload, or native screenshots.
- Running the GitHub CI workflow on GitHub (the Node-runner workflow is supplied, not yet remotely executed).
- Catalog approval or publication. The parent owns installation, independent review and external writes.

Before claiming native installation, the owner should read back the installed entry, enable through the native Plugins UI, open the route, focus/switch real sessions and confirm source/window/budget metadata. Do not restart an active session solely to obtain a screenshot. Disable/remove using the owning installation mechanism to verify teardown. No external writes or application restarts were performed by this implementation task.
